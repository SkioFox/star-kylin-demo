## 0. 文档用途

本文件是 MVP 的执行清单，用来回答每个任务的目标、边界、输入、产出、依赖和完成证据。它不新增需求或技术架构：

- 范围、验收和完成定义以 `MVP-demo需求.md` 为准。
- 架构、接口、安全实现和打包方式以 `MVP技术方案.md` 为准。
- 可见页面、状态、交互和视觉差异以 UI 基线为准。
- 本文件只负责把上述内容转成可执行工作包并维护任务状态。

任务状态统一使用：`待开始 / 进行中 / 开发实现完成、外部门禁待确认 / 外部输入待确认 / 已阻塞 / 已完成`。只有退出条件全部满足且证据可复核时，任务才能标记为“已完成”。

## 1. 共同执行规则

### 1.1 范围规则

- 只在 `mvp-demo/app` 实现正式应用；`ui-prototype` 继续作为视觉和交互基线，不直接作为 Qt 外壳运行时。
- 不引入真实 CAS、权限中心、真实行情、通用 JSBridge、原生 IPC、自动更新或生产治理能力。
- 不为尚未确认的麒麟版本、CPU 架构、Web Origin 或原生程序路径做猜测性兼容。
- 新增范围必须先修改需求；改变技术路线必须先修改技术方案；改变 UI 必须更新 UI 规格和验收记录。

### 1.2 完成证据规则

每个任务至少留下以下一种可复核证据：

- 源码、CMake、Manifest、资源或测试文件。
- 可重复执行的命令及结果。
- 指定环境截图、日志或验收记录。
- 依赖版本、许可证、SHA-256 或安装包内容清单。

“代码已写完”“本机看起来正常”不构成完成证据。Intel Mac 的结果不能替代 Linux/麒麟构建和麒麟真机验收。

### 1.3 代码与依赖规则

- 优先 Qt/C++ 标准能力，不引入未被任务明确需要的第三方 C++ 依赖。
- Manifest 使用 Qt JSON API；测试使用 Qt Test/CTest；打包使用 CMake install/CPack DEB。
- ECharts 和选用的 Lucide SVG 固定版本、本地化并附许可证；运行时不执行 `npm install` 或访问 CDN。
- 安全红线 S1–S6 的失败路径必须与成功路径一起实现和测试。
