## 3. 遗留问题与风险

1. 当前 amd64 包为约 500 KB 的薄包，依赖系统 Qt/QtWebEngine；客户机器无外网时，必须确认内网 APT 源、离线依赖包集合或改为自带运行时。
2. 当前包声明 `libc6 (>= 2.34)`，而客户 glibc 版本尚未采集。客户内核版本不能用于推导 glibc，因此不能宣称可安装运行。
3. Qt 兼容性不能只检查 Qt Core；还需核对 QtWebEngine、QML 模块、`QtWebEngineProcess`、Chromium `.pak`、locales 和字体。
4. Ubuntu 20.04 Dockerfile 只是较低 glibc 候选构建基座，尚未证明满足当前 QML/WebEngine 或客户麒麟运行时。
5. ARM64 包尚未生成，ARM64 真机、运行依赖、WebEngine 渲染和安装包验收均未开始。
6. 客户真实 Web 页面、Native 固定程序路径/参数、目标网络摆渡方式和许可证来源仍待确认。

## 4. 下周工作规划

### P0：关闭客户 amd64 T0A.0 基线采集

- 在客户 amd64 麒麟参考机执行只读采集脚本，归档 `star-kylin-amd64-baseline-YYYY-MM-DD.txt`。
- 核实 glibc、Debian 架构、Qt、QtWebEngine、QML 模块、`QtWebEngineProcess`、会话类型和字体基线。
- 基于结果确定 amd64 构建基座与 Qt 装载策略，不再依赖 Ubuntu/Kylin 版本猜测。

### P0：明确内网离线交付路径

- 确认客户机器是“可访问内网 APT/制品库”还是“完全隔离”。
- 若有内网源，使用客户麒麟实际包名完成依赖模拟安装和干净机安装验证。
- 若完全隔离，准备经批准摆渡的离线依赖包集合，或评估自带 Qt/QtWebEngine 运行时的包内容和许可证责任。

### P1：完成 amd64 麒麟验证与重建决策

- 在同基线 amd64 麒麟测试机执行依赖模拟、空 WebEngine 冒烟、K 线页面和安装/卸载验证。
- 若 glibc 或 Qt 不满足，使用客户麒麟/sysroot 或经验证的低 glibc 基座重建；检查实际 DEB `Depends`、QML import 和 WebEngine 资源。
- 记录 A01-A13 中 amd64 可执行项的截图、日志与已知问题。

### P1：建立 ARM64 原生构建通道

- 获取 ARM64 麒麟真机或 ARM64 Linux Builder；优先 ARM Mac/ARM64 Linux 原生容器或远程 ARM64 buildx Builder。
- 运行同一 `build-deb.sh` 生成真实 `arm64` DEB，检查 SHA、DEB 字段和 AArch64 ELF。
- 在 ARM64 麒麟机完成 T0A 基线采集后，再进行 QtWebEngine、K 线和安装包验证。

### P2：冻结 T0B 演示内容

- 确认真实 Web 入口、导航/资源 Origin、证书前提与离线夹具替换策略。
- 确认验收机 Native 程序绝对路径和固定参数。
- 在目标 QtWebEngine 验证 ECharts 6.1.0，冻结离线资源、许可证和 Mock 数据。
