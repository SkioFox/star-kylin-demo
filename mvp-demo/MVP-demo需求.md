## 1. MVP 目标

在一台明确的麒麟 V10 验收机上交付一个可安装、可启动、可完整演示的桌面应用，验证 Qt/QML 门户外壳、Mock 权限、受控 WebView、原生应用拉起和离线 K 线的最小闭环。

### 1.1 验收可见结果

1. Mock 用户成功登录后进入工作台。
2. `demoA` 与 `demoB` 显示不同菜单和应用入口。
3. Web 业务在标签中加载，支持刷新、加载反馈、错误恢复和越界拦截。
4. 从只读白名单拉起一个固定麒麟应用；缺失或启动失败时反馈明确。
5. K 线展示蜡烛、成交量、日/周/月周期、缩放、平移、十字线和重置，数据全部为 Mock。
6. 工作台支持打开、切换和关闭 Web/K 线任务，状态与焦点行为符合 UI 基线。
7. 产出目标 CPU 架构的 `.deb`，在干净的同基线麒麟机器完成安装、桌面/命令行启动、演示和卸载。
8. 指定真机上连续操作无崩溃、持续白屏或明显卡死，并记录一次资源基线。

### 1.2 安装包交付解释

- 麒麟安装包与 CPU 架构绑定，不存在同时运行于 ARM64 和 x86_64 的单一通用二进制。
- MVP 至少交付 T0A 锁定的验收机架构包。
- 若验收范围同时包含 ARM64 和 x86_64，则分别交付 `arm64`、`amd64` 两个 `.deb`，并在各自真机验收。
- “可运行在麒麟”只指 T0A 记录的麒麟版本、补丁基线、CPU 架构和 Qt 运行时组合，不泛化为所有麒麟版本。

## 3. 安全红线

以下约束在 Demo 中也不得删除：

- **S1 固定程序**：QProcess 只能使用 Manifest 中的绝对程序路径和固定参数；禁止 Shell、PATH 搜索、用户输入路径和候选程序回退。
- **S2 受控 Web**：顶层导航、重定向、新窗口和资源请求必须按精确 URL/Origin 白名单校验；禁止 HTTP 降级、通配 Origin、下载和忽略证书错误。
- **S3 假凭证**：仅使用 `demoA/demo-only`、`demoB/demo-only`；不得使用、记录或提交真实银行凭证。
- **S4 假行情**：K 线只读取随包 Mock 数据；运行时不连接真实行情、CDN 或公网。
- **S5 无特权 Bridge**：不实现 QWebChannel 或可访问文件、设备、凭证的通用 JSBridge。
- **S6 受控安装**：包维护脚本不得自行联网下载或执行动态脚本；依赖只能通过 `.deb` 声明并由批准的内网源/离线包满足；不得修改系统证书与安全策略。

## 7. 已定技术约束

详细实现以 [MVP技术方案.md](./MVP技术方案.md) 为准，本需求只冻结以下不可随意变更的决策：

- **语言与 UI**：C++17、Qt Quick/QML、Qt Quick Controls 2、CMake。
- **Web 容器**：QtWebEngine；业务页使用内存会话 Profile，K 线使用独立离线 Profile。
- **Mock**：应用进程内本地桩，不搭 HTTP Mock 服务。
- **配置**：一份编译进 `qrc` 的只读 `manifest.json` 是用户、角色、模块和白名单的唯一来源。
- **K 线**：本地 ECharts `6.1.0`，兼容性由 T0A/T0B 验证；不实现 JSBridge。
- **原生启动**：QProcess 直接使用固定程序和固定参数，不经 Shell。
- **安装包**：CMake install + CPack DEB；目标架构包必须在干净麒麟机验证。
- **运行时**：优先依赖验收镜像中受控的系统 Qt；若不满足，则随包提供完整 Qt/QML/QtWebEngine 运行资源并承担许可证与维护要求。

## 8. Manifest 契约

示例结构：

```json
{
  "schemaVersion": 1,
  "users": {
    "demoA": { "password": "demo-only", "role": "roleA" },
    "demoB": { "password": "demo-only", "role": "roleB" }
  },
  "roles": {
    "roleA": ["appWeb", "appKline"],
    "roleB": ["appWeb", "appNative"]
  },
  "modules": [
    {
      "id": "appWeb",
      "type": "web",
      "entryUrl": "qrc:/web-demo/index.html",
      "allowedLocalPrefixes": ["qrc:/web-demo/"],
      "allowedNavigationOrigins": [],
      "allowedResourceOrigins": []
    },
    {
      "id": "appNative",
      "type": "native",
      "program": "/usr/bin/<固定程序>",
      "args": []
    },
    {
      "id": "appKline",
      "type": "kline",
      "entryUrl": "qrc:/web-kline/index.html"
    }
  ]
}
```

最低校验要求：

- `schemaVersion` 正确；用户、角色、模块 ID 非空且唯一。
- 用户引用的角色、角色引用的模块必须存在。
- 模块类型只允许 `web`、`native`、`kline`。
- `qrc` URL 必须位于模块自己的资源前缀；远程入口只允许 HTTPS 和精确 Origin。
- Native `program` 必须为 Manifest 中的绝对路径，参数只能来自只读清单。
- K 线入口必须为应用自身资源，不能替换为远程行情页面。
- 解析失败、字段缺失、未知类型、重复 ID 或错误引用时拒绝进入工作台，显示配置错误页。

## 12. 诚实边界

- 本 Demo 只证明指定麒麟/CPU/Qt 基线上的可安装和可演示，不证明兼容所有麒麟版本或硬件。
- ARM64 与 x86_64 是独立二进制；未在对应真机验收的架构不得标记为支持。
- Intel Mac 只用于编码和原型验证，不能产出可宣称通过麒麟验收的最终 `.deb`；最终包必须来自对应架构的 Linux/麒麟构建通道并经过麒麟真机验收。
- Mock 登录、权限和行情不证明真实 CAS、权限中心或行情接入。
- 默认离线 Web 演示页不证明真实内网页面兼容；替换真实页面后必须重跑 A05–A07。
- “无明显卡顿”只作演示判断；记录的启动和内存数据不是生产 SLA。
- 原生应用以独立窗口启动，不嵌入标签，不实现 IPC 或统一进程管理。
- `.deb` 只覆盖 MVP 安装闭环；生产签名、灰度、自动升级、回滚和全量 SBOM 治理另行设计。
