# 国密链路 —— 专题设计

> 版本 v0.1 ｜ 2026-07-21 ｜ 关联 REQUIREMENTS §5 N5 ｜ 按评审第 5 点拆分
> 原则:**国密不是一个统一测试项**。原生 SDK 支持国密**不代表** Chromium 网络栈支持。须**分链路**明确并各自验证。

## 三条链路(各自独立确认)

| # | 链路 | 由谁发起 | 国密可行性关键 |
|---|---|---|---|
| L1 | **QtWebEngine/Chromium 加载子应用** | 内嵌 Chromium 网络栈 | Chromium 默认**不支持国密套件**;需国密改造版 Chromium、或**网关终止国密**转普通 TLS 给内网 |
| L2 | **Qt 原生网络 SDK**(F6.1) | 原生外壳 | 需集成国密库(如 GmSSL/铜锁)替换/扩展 TLS 后端 |
| L3 | **CAS / 权限中心 / 审计平台通信** | 门户后端/BFF | 取决于对端是否支持国密;可能各不相同 |

## 每条链路须明确的属性(逐条填写)
- 协议版本(TLCP/国密 TLS 版本)
- 密码套件(SM2/SM3/SM4 组合)
- 证书体系(国密双证书 / CA 来源)
- 密码模块(软实现 / 密码机 / USBKey)
- **是否允许网关终止国密**(网关侧终止后内网走普通 TLS,可大幅降低客户端改造量)

## 待确认(**M-1 开始前必须取得,不再以"若已知范围"处理**)
1. 三条链路各自是否强制国密?
2. 是否允许 L1 由网关终止国密(决定是否需国密版 Chromium,这是最大成本项)?
3. 指定的国密库/密码机/证书体系?
4. 是否有行内既有国密网关可复用?

> 影响:若 L1 必须端到端国密且不允许网关终止,则需国密版 QtWebEngine/Chromium,工作量与维护(CVE 跟随)风险显著上升,须在 ADR-0001 版本策略中专门评估。
