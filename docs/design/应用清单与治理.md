# 应用清单与运行治理 —— 专题设计

> 版本 v0.1 ｜ 2026-07-21 ｜ 关联 REQUIREMENTS §4.4 ｜ 按评审第 6 点补齐
> 目标:F4.1 的"注册/加载/卸载"必须有**契约**——谁注册、配置从哪来、如何审批与回滚。

## 一期最小要求:签名的应用清单
不强制自建管理后台,可复用行内配置分发;但**清单格式、签名、更新、回滚必须成为需求**。

### 清单字段(每个子应用一条)
| 字段 | 说明 |
|---|---|
| `appId` | 唯一标识 |
| `entryUrl` | 入口 URL |
| `allowedOrigins` | 允许来源(白名单,供 CSP/Bridge) |
| `profileGroup` | Profile 分组(默认 `shared`,例外 `isolated`,见 ADR-0003) |
| `casService` | 该子应用的 CAS Service 标识(如适用) |
| `bridgeCapabilities` | 授权的 Bridge 能力集(最小授权) |
| `icon` / `name` | 工作台展示 |
| `version` | 版本 |
| `openMode` | 打开方式(标签/新窗口) |

### 治理规则
- **签名**:清单须签名,门户启动时校验,防篡改。
- **更新**:清单版本化,支持灰度/全量下发;门户拉取或推送方式与行内配置分发对齐。
- **回滚**:保留上一版本,异常可回滚。
- **审批**:清单变更(尤其 `bridgeCapabilities`、`profileGroup`)需走审批流。

## 运行治理责任(必须落到人/周期)
- **QtWebEngine/Chromium CVE**:跟踪与升级的责任人、周期(银行安全要求)。
- **SBOM**:交付物料清单,含第三方库与许可证(呼应 ADR-0001 授权合规)。
- **安装包更新**:`.deb` 升级/回滚机制与责任方。
