# JSBridge —— 专题设计

> 版本 v0.2 ｜ 2026-07-21 ｜ 关联 REQUIREMENTS §4.5 ｜ 按评审第 4 点补齐落地级边界

## 目标
让**授权的** web 子应用受控调用门户原生能力(通知、打印、文件选择、缓存、设备信息等),并支持原生向 web 推事件。

## 通道
- 基于 QtWebEngine 的 `QWebChannel` 注入受控对象,或统一 `bridge.invoke(capability, params)` 门面。
- 注入的能力集由子应用**授权清单**决定,未授权能力不注入。

## 安全模型(落地级,银行重点)

### 绑定与撤销
1. **绑定到 `QWebEnginePage` + 精确 `scheme://host:port`**,不能只按 Profile 授权(同 Profile 内不同页面权限不同)。
2. **页面跳转(navigation)后立即撤销 Bridge**,重新按新 Origin 评估是否注入。
3. **限制 iframe、`window.open` 弹窗、重定向后页面**访问 Bridge —— 仅顶层且 Origin 匹配的页面可用。
4. **每次调用重新校验当前 Origin**,不信任首次注入时的判定(防跳转后残留)。

### 输入与调用
5. **参数校验**:类型、长度上限、枚举白名单;**文件路径规范化**(禁目录穿越、限定可访问根)。
6. **调用超时**与频率限制,防滥用/悬挂。
7. **高风险能力用户确认**:文件读写、打印、设备访问等须弹原生确认框,不静默执行。

### 审计与凭证
8. **审计脱敏**:记录能力名、子应用、Origin、结果码;**参数脱敏**,不把业务数据/敏感字段写进日志。
9. **凭证能力默认关闭**:不通过 Bridge 把 CAS/会话凭证交给页面。
10. **登录页/被劫持的跳转页绝不获得 Bridge** —— 与上面的 Origin 重校验 + 跳转撤销共同保证。

### 最小授权
11. 子应用只拿完成业务所需的最小能力集;能力清单进应用清单(见 `应用清单与治理.md`),变更需审批。
