# JSBridge —— 专题设计

> 版本 v0.1 ｜ 2026-07-21 ｜ 关联 REQUIREMENTS §4.5

## 目标
让授权的 web 子应用受控调用门户原生能力(通知、打印、文件选择、缓存、设备信息等),并支持原生向 web 推事件。

## 通道
- 基于 QtWebEngine 的 `QWebChannel` 注入受控对象;或统一走一个 `bridge.invoke(capability, params)` 门面。
- 每个 Profile/子应用注入的能力集由其**授权清单**决定,未授权能力不注入。

## 安全模型(银行重点)
1. **域名白名单**:仅白名单来源可访问 bridge,其余注入空对象。
2. **能力级鉴权**:每个能力标注所需权限,调用前校验(权限来自权限中心,见权限专题)。
3. **敏感能力默认关闭**:如"获取登录凭证/token"类能力默认不暴露,确需时单独审批 + 审计。
4. **调用审计**:能力名、子应用、参数摘要、结果写审计日志。
5. **最小授权**:子应用只拿完成业务所需的最小能力集。

## 不做
- 不通过 bridge 把 CAS/会话凭证明文交给子应用页面(见 SSO 专题)。
