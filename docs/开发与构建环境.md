# 开发与构建环境

> 版本 v0.1 ｜ 2026-07-21 ｜ 关联 REQUIREMENTS §6、docs/M-1-可行性验证.md
> 现状约束:开发机为 **Intel 芯片 Mac**;代码在**外网**编写,需**摆渡到内网**运行与验证。

## 1. 核心结论
- Qt/QML + QtWebEngine 可在 macOS 上写与跑,**日常业务/界面逻辑能在 Mac 上迭代**。
- **交付物是麒麟(Linux)的 `.deb`(ARM64 + x86_64)**,macOS 原生**产不出、也验证不了**麒麟相关行为(`.deb`、托盘/DPI/主题、X11/Wayland、国密、性能)。
- 因此**不能只在 Mac 上闭环**:必须有 Linux 构建环节 + 内网真机验证。

## 2. Intel Mac 的特有约束
- Intel Mac 是 **x86_64**:可较顺畅跑 **x86_64 麒麟 VM**(VMware Fusion / VirtualBox / UTM)做本地冒烟测试。
- **ARM64(飞腾/鲲鹏)在 Intel Mac 上只能 QEMU 模拟**,速度慢、不适合日常;**ARM64 的真实功能与性能验证只能在内网 ARM 真机**(M-1)。
- 影响:开发期以 x86_64 为主验证,**ARM64 差异属高风险项,必须尽早在内网真机验证,不能拖到后期**。

## 3. 分层环境

| 层 | 位置 | 用途 | 说明 |
|---|---|---|---|
| 编码 | Mac(外网) | 写码、Qt 本地跑、单元测试 | 业务/QML 逻辑快速迭代 |
| 冒烟 | Mac 上 **x86_64 麒麟 VM** | 近似麒麟环境自测 | 验证系统集成大部分行为(x86 侧) |
| 构建 | **容器化 Linux 构建** | 出 `.deb` | x86_64 原生;ARM64 需模拟或转内网/CI |
| 验证 | **内网麒麟真机**(飞腾+ x86) | M-1 及正式验证 | 性能/国密/合规/ARM64 的**唯一权威结论** |

## 4. 外网→内网 摆渡与"内网无公网"问题(重点)
内网通常**无公网访问**,且外部代码/制品需经**受控摆渡**(跳板机/文件摆渡系统/审批介质)进入。由此:
- **依赖必须离线化**:Qt(离线安装包)、apt/deb 依赖(内网镜像源或随包)、第三方库(vendored)、构建镜像(导出为 tar 摆渡)。外网准备齐,内网不能临时联网拉取。
- **可复现构建**:用固定版本的容器镜像 + 锁定依赖,保证"外网构建"与"内网构建"结果一致,减少内网调试。
- **摆渡对象选择**:摆渡**源码**(内网再构建,推荐,便于审计)还是摆渡**成品 `.deb`**(内网只验证)——取决于内网是否具备构建环境与行内规定。
- **合规**:代码/制品出入内网须符合行内规定;**个人 Mac 能否参与、代码能否带出**须先确认(见待确认)。

## 5. 建议工作流
1. Mac 外网:编码 + Qt 本地跑 + x86_64 麒麟 VM 冒烟。
2. 外网:容器化构建出 x86_64 `.deb`;准备离线依赖包与构建镜像。
3. 摆渡:源码或制品 + 离线依赖,经行内受控通道入内网。
4. 内网:在麒麟真机(x86 + **飞腾 ARM64**)构建(若摆渡源码)/安装验证;ARM64 与性能/国密以此为准。
5. M-1 结论回填 REQUIREMENTS §5 / 各 ADR。

## 6. 风险
| 风险 | 说明 | 缓解 |
|---|---|---|
| ARM64 验证滞后 | Intel Mac 无法有效测 ARM64 | 内网 ARM 真机尽早介入,M-1 必含 ARM |
| 反馈循环长 | 外网改→摆渡→内网验,周期长 | 尽量在 x86 麒麟 VM 前移问题;内网留常驻验证机 |
| 内网无公网 | 依赖拉不到 | 依赖全离线化 + 可复现构建镜像 |
| 合规阻断 | 代码不允许带出/个人机不允许 | **先确认**,可能改为内网开发机 |

## 7. 待确认
1. **个人 Mac 能否参与开发、代码能否带出内网?** 若否,改用行内配麒麟开发机(整个模式随之变)。
2. 内网是否具备构建环境与镜像源?摆渡源码还是成品?
3. 内网是否提供**飞腾 ARM64 真机**供开发期(非仅验收期)使用?
4. 摆渡通道与频率(决定反馈循环长度)。
