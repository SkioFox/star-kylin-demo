# 行内对接确认清单

> 版本 v0.1 ｜ 2026-07-21 ｜ 汇总各文档"待确认/待调研",按阻塞层级排序
> 用途:直接拿去与行内各团队对接。**P0/P1 未清,不进 M0。**

## 优先级说明
- **P0 阻塞开发模式**:不定则不知道"在哪、用什么机器、怎么交付代码"。
- **P1 阻塞架构**:不定则核心方案无法定稿,可能推翻现有假设。
- **P2 阻塞设计定稿**:不定则专题设计悬空,但不改变大方向。
- **P3 基线/流程**:多在 M-1 核定或走签字流程。

---

## P0 — 阻塞开发模式(最先问)

| # | 问题 | 为什么重要 / 答案影响 | 对接方 |
|---|---|---|---|
| P0-1 | **个人 Mac 能否参与开发?代码能否带出/带入内网?** | 若否,"Mac 外网开发"整套不成立,改为**行内配麒麟开发机**。决定开发模式根基。 | 安全合规 / 信息科技管理 |
| P0-2 | 内网是否具备构建环境与镜像源?摆渡**源码**还是**成品 .deb**? | 决定离线依赖准备量与内网调试方式。 | 桌面运维 / DevOps |
| P0-3 | 内网能否提供**飞腾 ARM64 真机**供**开发期**(非仅验收)使用? | Intel Mac 测不了 ARM64;无真机则 ARM 风险全压到后期。 | 桌面运维 |
| P0-4 | 外网→内网摆渡通道与频率? | 决定反馈循环长度,影响排期。 | 安全合规 / 运维 |

## P1 — 阻塞架构(进 M0 前必须定)

| # | 问题 | 为什么重要 / 答案影响 | 对接方 |
|---|---|---|---|
| P1-1 ⭐ | **行内现有 Windows 应用"登一次、开其他系统免登",底层是怎么做的?**(域集成 Kerberos/AD? 客户端 agent 持票? 浏览器 CAS?) | **最高优先。** 决定门户身份闭环(P1-2)与 Profile 取舍(P1-3);若为域/agent 机制,现有"浏览器 CAS"假设需推翻。 | 企业认证 / 桌面团队 |
| P1-2 | **门户身份闭环**:登录后门户如何**安全获知当前用户是谁**?(BFF 注册 CAS Service 校验 ST / 本地回环收 ST / 复用行内机制) | 不解则"登录后展示有权限应用"做不了。依赖 P1-1。 | 企业认证 |
| P1-3 | **Profile 与全局 SSO 取舍**:可接受"高风险应用独立 Profile 需再登一次"吗? | 独立 Profile 会破坏免登,三者不可兼得;需业务确认取舍。 | 安全合规 / 业务方 |

## P2 — 阻塞设计定稿

| # | 问题 | 为什么重要 / 答案影响 | 对接方 |
|---|---|---|---|
| P2-1 | **国密分三链路**(Chromium加载子应用 / 原生SDK / CAS等后端)各自是否强制?**是否允许网关终止国密?** | 若 L1 端到端强制且不许网关终止 → 需国密版 Chromium,成本/CVE 风险剧增。**M-1 前必须取得。** | 安全合规 / 密码管理 |
| P2-2 | CAS 版本/协议(2.0/3.0、是否 REST);是否强制 CA 证书登录;门户与子应用信任域关系 | 定认证实现细节。 | 企业认证 |
| P2-3 | 权限中心对接协议与数据模型(接口/SDK、角色-资源-操作粒度) | 定权限加载实现。 | 权限中心团队 |
| P2-4 | 应用清单:格式/签名/更新/回滚规则;复用哪套行内配置分发 | 定子应用治理契约。 | DevOps / 安全 |
| P2-5 | QtWebEngine/Chromium **CVE 升级、SBOM、安装包更新**责任人与周期 | 银行安全硬要求。 | 安全合规 / 项目管理 |
| P2-6 | 各子应用是否支持 **CAS 后端登出(SLO)通知** | 决定登出第③层能否保证。 | 各子应用团队 |

## P3 — 基线 / 流程

| # | 问题 | 为什么重要 / 答案影响 | 对接方 |
|---|---|---|---|
| P3-1 | V10 具体子版本、自带 Qt/QtWebEngine 版本、**默认合成器 X11/Wayland** | M-1 核定;合成器决定二期窗口嵌入可行性。 | 桌面运维 |
| P3-2 | 飞腾/鲲鹏具体型号基线(至少一款作性能基准机);是否需龙芯 LoongArch | 定构建/性能目标机。 | 桌面运维 |
| P3-3 | 首批接入子应用清单及各自登录/权限现状 | 定 M-1/M1 验证对象与适配量。 | 业务方 |
| P3-4 | 等保定级 checklist、审计平台对接方式、数据落地/防截屏要求 | 定 N6/N7 及数据安全实现。 | 安全合规 |
| P3-5 | Qt **授权方式(商业/LGPL)** 与合规交付清单 | 银行法务/采购必过项。 | 采购 / 法务 |
| P3-6 | **范围正式签字**:一期只做 web、K 线与原生列二期(ADR-0004) | 冻结范围,避免范围争议。 | 需求方 |
