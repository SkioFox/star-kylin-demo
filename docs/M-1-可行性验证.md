# M-1 可行性验证

> 版本 v0.1 ｜ 2026-07-21 ｜ 关联 REQUIREMENTS §6
> 目的:在**真机**上证明关键路径可行,并**锁定 §5 非功能指标阈值**。性能/安全验证从这里开始,不推迟到 M4。

## 环境
- 硬件:飞腾 **D2000**(ARM64 基准机)+ 一台 x86_64。
- 系统:麒麟 **V10** 指定镜像(记录子版本、内核、默认合成器 **X11/Wayland**)。
- Qt/QtWebEngine:记录镜像自带版本与对应 Chromium 版本(供 ADR-0001 版本/CVE 决策)。

## 验证项与判定
| # | 验证项 | 判定标准 | 产出 |
|---|---|---|---|
| V1 | QtWebEngine 能在两架构 V10 正常渲染真实业务页面 | 页面正常、无渲染/字体/输入法致命问题 | 兼容性记录 |
| V2 | **标准 CAS 跳转免登**:内嵌 webview 登录 CAS,第二个子应用免登 | 第二个子应用无需再登 | SSO 可行结论 |
| V3 | 一个**真实行内 web 子应用**端到端可用 | 登录→业务操作跑通 | 子应用适配问题清单 |
| V4 | `.deb` 在两架构安装/卸载/签名校验 | 静默安装成功、可卸载干净 | 打包基线 |
| V5 | 资源占用与启动实测 | 记录空载/3子应用内存、冷启动耗时 | **回填 N1/N3 阈值** |
| V6 | 默认合成器判定 | 确认 X11 或 Wayland | 决定 `type: embed` 可行性(二期) |
| V7 | 原生应用**拉起**可行性(为二期探路) | QProcess 拉起一个麒麟原生应用并纳入管理 | 二期风险评估 |
| V8 | 国密链路探测(若已知范围) | 国密 TLS 握手可行性 | M3 前置结论 |

## 输出
1. 各项 Pass/Fail + 问题清单。
2. **锁定** REQUIREMENTS §5 的 N1–N4/N8 具体阈值(替换模板值)。
3. 版本/授权/合成器等待确认项的真机答案,回填对应 ADR/专题。

## 依赖
- 真机与 V10 镜像到位;一个可用的真实 web 子应用及其 CAS 接入;行内 CAS 测试环境。
