# M-1 可行性验证

> 版本 v0.1 ｜ 2026-07-21 ｜ 关联 REQUIREMENTS §6
> 目的:在**真机**上证明关键路径可行,并**锁定 §5 非功能指标阈值**。性能/安全验证从这里开始,不推迟到 M4。

## 环境
- 硬件:飞腾 **D2000**(ARM64 基准机)+ 一台 x86_64。
- 系统:麒麟 **V10** 指定镜像(记录子版本、内核、默认合成器 **X11/Wayland**)。
- Qt/QtWebEngine:记录镜像自带版本与对应 Chromium 版本(供 ADR-0001 版本/CVE 决策)。

## 测量方法(所有性能项统一)
- **采样次数** N≥20;去掉首个预热样本另记(冷/热分开)。
- **冷/热缓存**分别测:冷=清缓存后首次;热=已加载态。
- **计时起止点**逐项写明(见下表"计时定义")。
- **P95** = 排序后第 95 百分位;同时记录 P50/P99 供参考。
- 阈值 = **M-1 实测分布 + 业务可接受值**共同确定,**不单纯按实现倒推**。

## 验证项与判定
| # | 验证项 | 判定/计时定义 | 回填 |
|---|---|---|---|
| V1 | QtWebEngine 在两架构 V10 渲染真实业务页面 | 无渲染/字体/输入法致命问题 | 兼容性记录 |
| V2 | **门户身份闭环**(SSO-CAS §3):登录后门户能安全获知当前用户身份 | 能取到身份并成功查权限中心 | **解 F2.0 阻塞** |
| V3 | **免登:同 Profile vs 跨 Profile 两种都测**(ADR-0003) | 同 Profile 第二应用免登;跨 Profile 预期需再登,如实记录 | **解 Profile 取舍** |
| V4 | 一个**真实行内 web 子应用**端到端可用 | 登录→业务操作跑通 | 子应用问题清单 |
| V5 | `.deb` 两架构安装/卸载/签名校验 | 静默安装成功、卸载干净 | 打包基线 |
| V6 | **N1 冷启动** | 计时=进程启动→工作台可交互;冷缓存;N≥20 | **锁 N1** |
| V7 | **N2 子应用打开** | 计时=点击→页面可交互;记录白屏时长 | **锁 N2** |
| V8 | **N4 标签切换** | 计时=切换触发→首帧 | **锁 N4** |
| V9 | **N3 内存** | 空载 + 含 3 子应用常驻;定 N/M | **锁 N3** |
| V10 | **N8 断网自愈** | 注入断网→订阅恢复耗时 | **锁 N8** |
| V11 | 默认合成器判定 | 确认 X11 / Wayland | 决定 embed 可行性(二期) |
| V12 | 原生应用**拉起**可行性(二期探路) | QProcess 拉起并纳入管理 | 二期风险 |
| V13 | **国密分三链路**探测(L1/L2/L3,见国密专题) | 各链路握手可行性 + 是否需网关终止 | M3 前置结论 |

## 输出
1. 各项 Pass/Fail + 问题清单。
2. **锁定** REQUIREMENTS §5 的 N1–N4/N8 阈值(V6–V10 覆盖,替换模板值)。
3. 解除架构阻塞:F2.0 身份闭环(V2)、Profile 取舍(V3)。
4. 版本/授权/合成器/国密等待确认项的真机答案,回填对应 ADR/专题。
