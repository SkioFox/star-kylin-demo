## 1. 文档用途与状态规则

本文件只把已评审的需求、UI 和技术方案转换为可执行工作包，不新增产品范围或架构决策：

- 需求、验收口径和范围边界以《需求分析与范围》为准。
- Qt/QML、数据、Web 安全、构建和打包实现以《技术方案》为准。
- 页面、密度、交互与可见状态以 UI 规格和 UI 验收记录为准。
- 正式代码只写入 `kylin-sky-demo/app/`；`ui-prototype/` 仅为视觉和交互参照，不能作为运行时实现。

任务状态使用：`待开始 / 进行中 / 开发实现完成、外部门禁待确认 / 外部输入待确认 / 已阻塞 / 已完成`。只有所有退出条件和完成证据均可复核时才可标记为“已完成”。

### 1.1 共同约束

- 首版只使用包内演示数据；不得称为真实行情、实时银行黄金报价或交易能力。
- 不接入真实 CAS、权限中心、生产 Web 账号、真实行情、数据库、Node 运行时、通用插件 SDK、通用 JSBridge 或第三方 C++ 图表库。
- Web 模块只打开只读 Manifest 中批准的入口；不提供地址栏、任意 URL、下载、证书绕过或跨 Profile 会话共享。
- 原生应用仅从清单的绝对路径和受限参数由 `QProcess` 启动，不执行 Shell、不搜索 PATH、不传递凭据。
- 新增范围先更新需求；改变架构先更新技术方案；改变可见 UI 或交互先更新 UI 规格和验收记录；每项实现、修复和验证均要在对应记录中留痕。

### 1.2 完成证据与环境定义

每个工作包至少留下源码或配置、可重复命令与结果、测试日志/截图、依赖与许可证清单中的一种以上证据。“本机看起来正常”不是完成证据。

`T1.1–T1.4 可用` 的操作化定义是：对应子任务的完成证据已在 Mac 开发环境或指定 Linux 开发环境可复核通过，**不要求**麒麟真机证据；麒麟真机构建、启动和包验证属于 T1 的最终完成门禁。这样 T2/T3 可以先行开发，但不能在 T0A 未关闭时宣称已完成麒麟适配。

Intel Mac、Apple Silicon Mac、Docker、QEMU 和非目标 Linux 只能用作开发辅助，不能替代 `amd64` 或 `arm64` 麒麟真机结论。两种架构均须由对应 Linux/麒麟构建通道产包，并在同架构干净麒麟机验收。
