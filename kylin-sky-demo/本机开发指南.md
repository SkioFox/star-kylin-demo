# 团队协作开发指南

本指南约定 `kylin-sky-demo/app` 在 macOS 和 Linux 上的日常开发方式，以及从克隆源码到合并、麒麟验收的协作边界。统一入口是 `app/tools/local-dev.sh`；它负责配置、增量构建、CTest、前后台启动和 Docker Linux 回归。

本机验证覆盖 C++、QML、Mock 认证、权限、离线行情、图表和受控 Web 页面，不替代银河麒麟 Qt 5.12、DEB、KySec、签名或固定麒麟本机程序验收。

## 新成员首次启动

以下流程是任何新开发设备的唯一入口。克隆仓库后不需要先连接麒麟 VM，也不需要安装 `.deb`：

```bash
git clone <repository-url> star-kylin-demo
cd star-kylin-demo
git switch main
cd kylin-sky-demo/app
./tools/local-dev.sh doctor
./tools/local-dev.sh test
./tools/local-dev.sh run
```

`doctor` 成功后会输出主机系统、CMake、Qt 和构建目录；`test` 必须通过才开始修改代码；`run` 打开正式 Qt 程序。若源码通过 ZIP 而不是 Git 获取，先恢复脚本执行位：

```bash
chmod +x tools/local-dev.sh tools/local-dev-macos.sh
```

每台新设备首次运行 `run` 后，使用 `operator / KylinDemo2026` 登录，至少打开自选、个股研究、指定业务、在线网页、网络验证和原生行情中心，验证窗口与 Qt WebEngine 均能正常启动。

## 支持矩阵

| 开发设备 | 正式程序本机运行 | 团队 Linux CTest | 目标包/真机结论 |
| --- | --- | --- | --- |
| Intel Mac | Qt 5.15.2 x86_64 | `linux/amd64` Docker | 仅 amd64 麒麟 VM/真机 |
| Apple Silicon Mac | Rosetta 下 Qt 5.15.2 x86_64 | 原生 `linux/arm64` Docker | 仅 arm64 麒麟 VM/真机 |
| x86_64 Linux | 系统 Qt 5 + WebEngine | 原生 `linux/amd64` Docker | 仅 amd64 麒麟 VM/真机 |
| ARM64 Linux | 系统 Qt 5 + WebEngine | 原生 `linux/arm64` Docker | 仅 arm64 麒麟 VM/真机 |

Qt `5.15.2` 是日常开发基线，因为它与客户环境的 Qt `5.12.12` 同属 Qt 5。开发设备不能生成或验证另一种架构的麒麟交付结论，也不能把 Ubuntu/Docker 结果当成麒麟验收。

## 统一日常命令

```bash
cd kylin-sky-demo/app
./tools/local-dev.sh doctor
./tools/local-dev.sh test
./tools/local-dev.sh run
```

`run` 以前台方式打开程序，关闭应用窗口或按 `Ctrl+C` 即可停止。需要后台运行时：

```bash
./tools/local-dev.sh start
./tools/local-dev.sh stop
```

`test` 会配置、增量构建并执行 CTest。修改 CMake、Qt 路径或缓存异常时执行 `./tools/local-dev.sh configure`；只清理目标文件执行 `./tools/local-dev.sh clean`。旧的 `local-dev-macos.sh` 保留为兼容入口，内部转发到统一脚本。

演示账号：`operator / KylinDemo2026`，或 `auditor / AuditDemo2026`。

## macOS

### Intel Mac

安装 Xcode Command Line Tools、CMake 3.16+ 与 Qt `5.15.2` 的 `clang_64` 及 `qtwebengine`。CMake 可通过 Homebrew 安装：

```bash
xcode-select --install
brew install cmake ninja
```

Qt 官方包可用 `aqtinstall` 安装：

```bash
python3 -m pip install --user aqtinstall
"$HOME/.local/bin/aqt" install-qt mac desktop 5.15.2 clang_64 -m qtwebengine -O "$HOME/Qt"
```

默认 Qt 路径是 `~/Qt/5.15.2/clang_64`。使用其他位置时：

```bash
QT_PREFIX="/path/to/Qt/5.15.2/clang_64" ./tools/local-dev.sh test
```

### Apple Silicon Mac

Qt 5.15.2 的公开 macOS `clang_64` 包是 x86_64，不能作为 ARM64 原生套件使用。安装 Rosetta 后沿用上面的 Qt 套件和统一命令，CMake 会显式产出 x86_64 应用，由 macOS 通过 Rosetta 启动：

```bash
softwareupdate --install-rosetta --agree-to-license
./tools/local-dev.sh test
./tools/local-dev.sh run
```

首次在每台 Apple Silicon 机器上必须完成一次 `doctor`、`test` 和人工登录/Web/K 线烟测后，才可作为该设备的本机 UI 开发基线。不要把 `CMAKE_OSX_ARCHITECTURES` 改为 `arm64`，除非团队引入并验证了包含 Qt WebEngine 的 ARM64 Qt 5 套件。

## Linux

Ubuntu 22.04/Debian 系 Linux 可使用系统 Qt 5 开发包：

```bash
sudo apt-get update
sudo apt-get install --yes build-essential cmake ninja-build \
  qtbase5-dev qtdeclarative5-dev qtquickcontrols2-5-dev qtwebengine5-dev \
  qml-module-qtquick2 qml-module-qtquick-controls2 qml-module-qtquick-window2 \
  qml-module-qtwebengine libqt5svg5-dev
```

之后不必设置 `QT_PREFIX`：

```bash
./tools/local-dev.sh doctor
./tools/local-dev.sh run
```

使用自行安装 Qt 时设置 `QT_PREFIX`，它必须包含 `Qt5Config.cmake` 和 `Qt5WebEngineConfig.cmake`。Linux 桌面会话的字体、GPU 或 WebEngine 沙箱问题应保留原始日志并报告，不要通过关闭安全策略来掩盖。

## 代码区域与协作边界

| 目录 | 用途 | 日常修改规则 |
| --- | --- | --- |
| `app/src/` | C++ 模型、Manifest 校验、Web/Native 安全边界、图表 | 修改后必须运行 `./tools/local-dev.sh test` |
| `app/qml/` | 正式 Qt Quick 界面和交互 | 修改后运行 `test`，并以 `run` 做对应页面烟测 |
| `app/resources/` | 只读 Manifest、离线市场数据、图标和本地 Web 页面 | 不得为开发机改写麒麟固定程序路径或放宽 Origin 白名单 |
| `app/tests/` | CTest 聚合测试 | 新增 C++/策略逻辑时补充或更新断言 |
| `ui-prototype/` | 浏览器视觉/交互评审物 | 不复制为正式运行时代码；视觉调整需同步正式 QML |
| `客户离线安装包/` | 已归档候选交付物 | 不作为日常开发目录，不覆盖已有候选包 |

本机“本机应用集成”出现固定程序缺失是预期的负向状态。不得为了本机方便把 Manifest 改成 PATH 搜索、Shell 命令、任意 URL 或本机真实账号。

## 每个变更的协作流程

1. 从最新 `main` 创建或更新个人分支，先执行 `./tools/local-dev.sh test`，确认基线可复现。
2. 只修改与任务直接相关的 `app/` 源码、测试或文档；不提交 `build-local-*`、日志、截图缓存或个人 Qt 配置。
3. 修改 C++、QML、资源、Manifest、URL 策略或 Native 启动逻辑后执行 `./tools/local-dev.sh test`。影响界面时再执行 `run` 做人工烟测。
4. 涉及跨平台 C++、QML、WebEngine 或资源加载时，设备具备 Docker 后额外运行 `./tools/local-dev.sh docker-test`。
5. 提交前检查 `git status --short` 与 `git diff --check`；提交说明写明功能范围、执行过的命令和未覆盖的平台。
6. 合并前由评审者确认自动测试、必要的人工烟测和目标架构影响；涉及 DEB 或安全边界时进入麒麟验证队列。

本项目不规定具体分支命名或代码托管平台。若团队采用 `main` + 功能分支，更新本地 `main` 使用：

```bash
git switch main
git pull --ff-only
git switch <feature-branch>
git rebase main
```

存在未提交工作时先提交或暂存，再更新分支；不要用强制覆盖命令丢弃他人或自己的改动。

## 一致的 Linux 回归

每台设备建议在推送前运行本机 CTest；涉及跨平台 C++、QML、WebEngine 或资源改动时，再运行与主机同架构的 Docker 回归：

```bash
./tools/local-dev.sh docker-test
```

该命令使用 `app/packaging/docker/Dockerfile` 构建 Qt 5.15/Ubuntu 22.04 开发镜像，并在 `linux/amd64` 或 `linux/arm64` 容器中构建和执行 CTest。首次下载较大，成功后 Docker 缓存会复用；团队应将成功的镜像推送到批准的内网镜像仓库，避免每台电脑重复下载 QtWebEngine。

Docker 只用于无界面 Linux 回归，不用于本机 GUI 展示，也不替代麒麟打包、安装或跨架构验证。Intel 机器不得用 QEMU 模拟 ARM64 关闭 ARM 结论。

## 验证责任与发布门禁

| 验证层 | 何时执行 | 责任设备 | 结论范围 |
| --- | --- | --- | --- |
| 本机 `test` | 每个功能变更 | 每位开发者 | C++、QML、资源和策略回归 |
| 本机 `run` | 影响界面或交互 | 变更开发者 | 当前主机的人工 UI 烟测 |
| `docker-test` | 跨平台/依赖风险变更 | 对应 host 架构开发机或 CI | Ubuntu Linux 同架构 CTest |
| 麒麟构建/CTest | 合并候选或发布候选 | 对应架构麒麟构建通道 | Qt 5.12 兼容性 |
| DEB 安装、KySec、签名和 GUI | 发布候选 | 对应架构干净麒麟机 | 可交付结论 |

amd64 与 arm64 的最后两层必须分别执行。Docker、Rosetta、QEMU、另一种架构的 Mac/Linux，均不能替代目标架构麒麟结论。

## 更新与边界

更新源码后不需要安装 `.deb`。在 `main` 分支使用快进更新；功能分支按上面的 rebase 流程同步：

```bash
git pull --ff-only
cd kylin-sky-demo/app
./tools/local-dev.sh test
```

若升级 Qt，继续使用 Qt 5 并包含 `qtwebengine`，先在每种开发机执行 `doctor`、`test` 与人工烟测。可用变量包括 `QT_PREFIX`、`CMAKE_COMMAND`、`CMAKE_BUILD_TYPE`、`KYLIN_SKY_BUILD_DIR` 和 `KYLIN_SKY_BUILD_JOBS`；它们只影响本机环境，不应提交到源码。

常见问题：

| 现象 | 处理方式 |
| --- | --- |
| `Missing Qt 5 qmake` 或 `Qt WebEngine is missing` | 按当前平台安装 Qt 5 + WebEngine，或设置正确的 `QT_PREFIX` 后重跑 `doctor` |
| `permission denied: ./tools/local-dev.sh` | 从 Git 克隆应保留权限；ZIP 来源执行上面的 `chmod +x` |
| CMake 缓存仍指向旧 Qt | 执行 `./tools/local-dev.sh configure`；仍异常时设置新的 `KYLIN_SKY_BUILD_DIR` 创建独立本机缓存 |
| 在线网页加载失败 | 检查开发网络、代理和批准来源可达性；不要修改 Origin 白名单绕过问题 |
| `docker-test` 提示 daemon 未运行 | 启动 Docker Desktop/Engine 后重试；首次构建下载较大属于正常现象 |

合并或发布前仍需在对应架构的麒麟通道执行 Qt 5.12 构建、CTest、DEB 内容检查、签名/KySec 与安装后 GUI 回归。更完整的目标环境要求见 [构建安装与签名说明.md](./构建安装与签名说明.md)。

## 原型预览

```bash
python3 -m http.server 4173 --directory kylin-sky-demo/ui-prototype
```
