## 1. 目标与边界

本方案将已通过 UI 评审的“麒麟工作台”实现为可在银河麒麟 V10 的 `amd64` 与 `arm64` 验收环境安装运行的 Qt 桌面应用。首版交付包含：登录与演示权限、原生市场观察、黄金报价查询、受控内网 Web、批准的在线网页、网络验证、固定本机应用拉起，以及双架构 `.deb` 安装闭环。

本阶段不接入真实 CAS、真实权限中心、生产行情、真实银行黄金报价、交易/申购、客户数据、通用 JSBridge、插件市场、在线升级或生产审计平台。所有行情和报价均来自包内本地演示数据；任何真实数据接入均须单独完成来源授权、数据口径与安全评审。

## 2. 技术决策

| 领域 | 选型 | 理由与边界 |
|---|---|---|
| 桌面与 UI | C++17、Qt Quick/QML、Qt Quick Controls 2 | 复用 `mvp-demo` 在麒麟 VM 的验证路径；QML 还原工作轨、标签和高密度工作区 |
| 原生市场图表 | C++ `QQuickItem` + Qt Scene Graph | K 线、分时、成交量、MACD、缩放和平移均原生渲染，不依赖 QtWebEngine 或 CDN |
| 市场数据 | `MarketDataService` + `QAbstractListModel` + `qrc` JSON fixture | 一个本地服务管理各市场数据、时间序列和选中对象；不搭本地 HTTP 服务 |
| Web 模块 | QtWebEngine、模块级 `QWebEngineProfile`、URL 策略 | Demo 按编译入包的批准清单隔离；生产阶段再以签名清单替换同一契约；原生市场模块不走 WebView |
| 应用配置 | 编译入 `qrc` 的只读 Manifest | Demo 阶段避免用户可写配置；生产阶段以签名、版本化 Manifest 替换同一契约 |
| 构建与测试 | CMake、CTest、Qt Test | 以单个 `test_all` 聚合测试降低 KySec 重复授权；内部保留资源、Manifest、URL、数据、启动器、权限、图表和 QML 八组断言，可支持 CPack DEB |
| 安装交付 | CMake install、CPack DEB | 每架构先产出可标准 `dpkg -i` 安装的未签名基线包；仅在目标强制策略下，从同一构件生成受信任签名变体 |

Qt 主版本、QtWebEngine/Chromium 版本、系统 Qt 或随包动态库策略，必须以两类麒麟验收机的实际基线为准；Intel Mac、QEMU 或非目标 Linux 的构建不能替代真机验收。

## 5. 市场与黄金数据

### 5.1 本地数据契约

`market-fixtures.json` 保存国内、全球、期货、黄金和研究对象的：`instrumentId`、名称、市场、报价字段、交易状态、OHLCV 序列、关联对象和资讯摘要。启动时完整校验：唯一 ID、合法价格、`high >= max(open, close)`、`low <= min(open, close)`、时间递增、非负成交量、报价单位与黄金产品字段齐全。

`MarketDataService` 使用其 GUI 线程归属的 C++ `QTimer` 每秒以受控的演示增量更新一个当前可见对象，并只更新对应 `QAbstractListModel` 行；首版不创建数据后台线程。切换周期时由同一数据集选择分时、日、周、月序列；缩放和平移只改变 `KlineChartItem` 的可视窗口，不重建页面或产生网络请求。

### 5.2 原生图表

`KlineChartItem` 是 `QQuickItem`，在 `updatePaintNode()` 使用 Qt Scene Graph 绘制网格、蜡烛、MA、成交量与 MACD。其公开属性仅包括：`seriesModel`、`period`、`visibleStart`、`visibleCount`、`showVolume`、`showMacd`。

- 滚轮缩放、拖拽平移和显式加减/重置按钮同时存在，不能只有手势。
- 通过属性绑定使自选详情、个股研究、指数详情、期货详情与黄金基准趋势复用同一图表组件，但各页面传入各自数据源与布局密度。
- 以文字、符号和颜色同时表示涨跌；不提供委托、买卖或账户动作。

### 5.3 黄金业务

黄金页显示银行、产品、买入价、卖出价、点差、日内变化与更新时间。`GoldQuoteModel` 继承通用市场表格模型的只读行能力，但额外校验“人民币元/克”、产品类别和报价时间；基准 `Au9999` 使用独立时间序列。

未来真实接入前必须审批：供应商或银行公开数据授权、请求频率、产品口径、交易时段、节假日规则、延迟标识和异常兜底。没有这些输入时，禁止把本地演示刷新说成实时查询。

## 6. Web、权限与原生应用

Manifest 的模块定义至少包含 `id`、`type`、`name`、`entryUrl`、`allowedNavigationOrigins`、`allowedResourceOrigins`、`profileGroup` 与 `bridgeCapabilities`。

- **指定业务**：固定批准入口，业务域 Profile；所有顶层导航、重定向、资源、弹窗、下载和证书失败由 `UrlPolicy` 拦截，业务系统自身继续二次鉴权。
- **在线网页**：只展示获批配置项；每个配置使用隔离 Profile，不共享内部会话，不提供 Bridge、下载或本机能力；禁止地址栏和任意 URL。
- **登录与角色**：Demo 使用包内 `operator / KylinDemo2026` 与 `auditor / AuditDemo2026` 两个演示用户和仅内存会话；凭证错误统一提示，应用退出即失效，不做失败锁定、超时续期、密码落盘或 token。`AppController` 与 QML 菜单均校验模块可见性，退出清理 Profile 的 cookie/cache。
- **本机应用**：Manifest 给出绝对路径和受限参数，`NativeLauncher` 经 `QProcess(program, QStringList)` 直接启动；不经 Shell、不做路径搜索、不传递凭据。

Demo Manifest 编译进 `qrc`。生产治理遵循仓库的 [应用清单与治理](../docs/design/应用清单与治理.md)：签名、版本化、审批与回滚另行接入，不在本阶段伪实现。

## 7. 构建、打包与环境门禁

1. 在两类目标麒麟机采集 CPU、`uname -m`、`dpkg --print-architecture`、glibc、Qt、QtWebEngine、`QtWebEngineProcess`、X11/Wayland、字体与 DPI 基线，并对每种架构运行最小 WebView、批准导航/越界拦截、Profile 清理和 150% 缩放用例。音视频编解码不在本期范围，不能据此作兼容性承诺。
2. 锁定同一 Qt 主版本与动态库策略，准备离线 Qt、WebEngine 资源、许可证和构建依赖。
3. 在对应 `amd64` 与 `arm64` Linux/麒麟构建通道执行 CMake、CTest、install、CPack，先保留未签名基线 `.deb` 及 SHA-256，并在未强制签名的目标机执行标准 `sudo dpkg -i` 安装验收。若目标麒麟启用 `verify-kylinsign`/`debsig-verify` 并拒绝基线包，再由受控构建通道使用受信任的麒麟开发或发行证书对同一 DEB（及其包内 ELF，如策略要求）执行 `kylinsigntool` 签名和验证。CPack 只负责生成 DEB，不替代签名。
4. 分别在干净目标机执行安装、启动、登录、各模块冒烟、卸载；交付未签名基线 `.deb`、SHA-256、依赖清单、许可证和验证记录，并按客户策略额外交付签名变体与签名验证结果。不得以 `dpkg --no-debsig`、关闭 KySec 或自签名并临时修改目标机信任库替代客户验收。

最终包不得包含浏览器原型、Node/npm、在线 CDN 依赖或用户可写的安全 Manifest。每个包的架构必须由 `dpkg-deb --field <pkg> Architecture` 与真机 `dpkg --print-architecture` 对照确认。

## 8. 测试策略

| 层级 | 重点 |
|---|---|
| 聚合单元测试 | 单个 `test_all` 进程依次覆盖 Manifest、登录、角色、标签、URL 策略、原生启动参数、fixture 数据不变量、K 线可视窗口计算；避免内容变更后八个独立 ELF 分别触发 KySec |
| QML 组件测试 | 标签焦点、选中对象联动、加载/空/错误状态、缩放/平移边界 |
| Web 容器测试 | 允许导航、越界拦截、新窗口/下载/证书失败、Profile 隔离 |
| 麟机集成测试 | QtWebEngine 启动、字体/DPI、输入法、20 次启动关闭、资源基线 |
| 打包验收 | `amd64` 与 `arm64` 安装、菜单入口、依赖完整性、卸载、包内容与许可证 |

关键验收包括：市场对象切换后报价与图表一致；图表周期、缩放和平移确实改变可视数据；黄金银行报价与基准图单位明确；在线网页不能跳出批准清单；未授权模块不能通过直接调用打开。

## 9. 关键风险与待确认

| 风险/输入 | 处置 |
|---|---|
| ARM64 QtWebEngine 依赖和构建慢 | 采用原生市场图表，WebEngine 仅保留 Web 模块；使用原生 ARM64 构建机或远程 buildx，不把 QEMU 结果作为验收 |
| 原生图表实现复杂度 | T5 先完成 Scene Graph、视窗与输入事件技术 Spike；未通过时调整实现范围与排期，不在集成阶段临时替换为 Web 图表 |
| Qt/Chromium CVE 与许可证 | 在环境门禁中锁定版本、动态链接策略、责任人和第三方清单 |
| 麒麟 DEB 签名策略 | T8 先验证标准未签名包是否可由目标机 `dpkg -i` 安装；仅在目标强制策略拒绝时接入受控签名证书。不得为兼容性关闭系统校验；两种结果分别留痕 |
| 真实市场或黄金数据 | 未授权前保持本地演示；接入前冻结数据契约、延迟、合规口径与故障策略 |
| Web 来源不完整 | Manifest 必须显式列入口、导航、资源 Origin；不以通配或关闭证书校验解决 |
| 原型与 QML 偏差 | 任务阶段逐页截图比对原型；视觉变更先更新 UI 规格和验收记录 |

## 11. V2 实施基线与差异收敛

### 11.1 实施目标

V2 不是仅替换颜色。它将现有 Qt 工程从“共享市场表格加右侧详情”的演示骨架，收敛为与 V2.1 原型一致的高密度桌面工作区：深蓝指挥轨、按分组的导航、可关闭任务标签、两层上下文条，以及分别按扫描、研究、比较、会话、矩阵、双向报价组织的金融页面。

本轮只把已在原型中确认的可见行为实现到 QML；不把浏览器原型的 HTML、SVG 字符串绘制或模拟 Web 内容直接复制进正式应用。原生图表继续使用 `KlineChartItem`，Web 安全控制面继续使用 `ManifestService`、`UrlPolicy` 和独立 `QQuickWebEngineProfile`。

### 11.2 V2 信息与组件架构

```text
Main.qml
  ├─ LoginPage              # V2 深蓝身份区 + 受控登录表单
  └─ AppShell
       ├─ CommandRail       # 角色、环境、网络、退出
       ├─ GroupedSidebar    # 市场观察 / 应用服务 / 原生能力
       ├─ TaskTabs          # 单实例、可关闭、相邻回焦
       ├─ ContextRail       # 工作台 / 当前模块，仅表达真实路径
       └─ ModuleHost
            ├─ WatchlistWorkspace
            ├─ ResearchWorkspace
            ├─ MarketOverviewWorkspace / GlobalWorkspace / FuturesWorkspace / GoldWorkspace
            ├─ WebModulePage # 外汇离线演示页或批准 HTTPS 配置
            ├─ NetworkWorkspace
            └─ NativeMarketWorkspace / NativeIntegrationWorkspace
```

首次实施以最少的可维护组件收敛：`AppShell` 负责导航、标签和容器；市场页面可共用报价头、周期工具条、状态标签和 `KlinePanel`，但不得共用会改变业务字段语义的表格。页面专用差异保留在对应 QML 中，避免再次形成“一张表换标题”的错误抽象。

### 11.3 V2 视觉令牌与桌面布局

| 令牌 | 值 | 使用规则 |
|---|---:|---|
| `command` | `#061A31` | 顶部指挥轨和主导航底座 |
| `rail` | `#082642` | 左侧分组导航 |
| `panelBlue` | `#0D5B8D` | 页面标题面与当前任务层 |
| `signal` | `#25D3E2` | 焦点、活动任务脊线与连接信号 |
| `gold` | `#E0B967` | 受控环境与身份提示，非通用高亮 |
| `canvas` | `#E9F1F7` | 数据工作区背景 |
| `paper` | `#FFFFFF` | 表格和分析面，不使用大圆角卡片 |
| `up` / `down` | `#C33C52` / `#18826B` | 行情涨跌；同时输出符号和文字 |

- 默认窗口为 `1280x800`，最小为 `1180x680`；核心验收视口为 `1280x720`、`1366x768` 和 `1440x900`，页面根容器不得出现纵向滚动。
- 布局使用 `RowLayout` / `ColumnLayout` 的可收缩轨道，图表和资讯在有限高度下优先收缩而非撑开父容器。`KlinePanel` 不得以固定高度遮挡资讯、五档或状态条。
- 所有深色区域的 `Text`/`Label`/`Button.contentItem` 显式设置前景色；激活周期、标签和面包屑均以可读文字、边界和信号脊线共同表示，不依赖 Qt Controls 默认调色。
- 数据使用等宽字体并右对齐。焦点、禁用、加载、空、错误和阻断状态的尺寸稳定；`Tab`、`Enter`、方向键、`Esc`、`Delete`/`Ctrl+W` 保持可用。

### 11.4 页面实现契约

| 页面 | QML 实现边界 | 默认与交互 | 禁止事项 |
|---|---|---|---|
| 登录 | 左侧深蓝身份说明，右侧受控表单 | 账号密码、提交中、统一错误、成功进入工作台 | 不落盘密码、不伪造真实认证 |
| 自选 | 可滚动扫描表 + 可拖动分析区 | 默认首个国内标的；分时/日周月、量能/MACD、热点和资金联动 | 把详情退化为静态报价卡 |
| 个股研究 | 对象池 + 主 K 线 + MACD/资讯 + 五档/资金侧栏 | 默认首个国内标的；对象切换驱动全部上下文 | 复用自选表的标题或固定五档数值 |
| 市场行情 | 国内指数比较和市场宽度 | 默认首个国内指数；指数趋势、涨跌家数、板块/资金摘要 | 伪装成单标的研究页 |
| 全球市场 | 美洲/欧洲/亚太会话及相对走势 | 默认首个全球指数；时区/开闭市状态可见 | 使用国内字段或国内数据改名 |
| 期货观察 | 交易所/品类矩阵、期限结构、日增仓与期市资讯 | 默认首个合约 | 使用证券成交额、交易买卖操作 |
| 黄金业务 | 银行产品买卖价/点差 + Au9999 基准 | 默认首个黄金产品或基准；价格单位为元/克 | 宣称真实报价或提供交易 |
| 指定业务 | `qrc:/web-demo/` 外汇演示台，经受控 Web 容器加载 | 无地址栏；来源、加载、刷新、拦截反馈明确 | 真实下单、自由网址、共享外部会话 |
| 在线网页 | 清单中批准的 HTTPS 配置项和独立 Profile | 仅显示批准来源；切换配置重建/切换隔离上下文 | 自由浏览、下载、证书绕过 |
| 网络验证 | 原生协议状态表和重试 | 演示检查、失败与恢复状态 | 输出认证头、Cookie 或把演示结果称为生产探测 |
| 原生行情中心 | 原生 `KlineChartItem` + 周期/缩放/状态 + 本机工具反馈 | 主图最高 360px，周期、缩放、平移可用 | Web 图表替代、超出工作区 |
| 本机应用集成 | Manifest 固定程序的启动清单和反馈 | 显示启动中、成功、缺失、拒绝、失败 | Shell、PATH 搜索或凭据传递 |

### 11.5 数据与图表收敛

现有 `MarketDataService` 继续是唯一包内演示数据源。V2 扩展 fixture 和模型角色以表达市场宽度、会话、交易所、期限结构、银行产品买卖价/点差和五档/资讯上下文；所有同页联动必须基于同一个 `instrumentId`，禁止在 QML 按页面硬编码另一份价格或五档数据。

`KlineChartItem` 保持 C++ Scene Graph 实现，并补齐：可见区价格/时间标签、分时走势、MA、成交量、MACD、十字线或当前点摘要，以及按 `instrumentId` 的数据尺度。周期、缩放、平移只改变视窗状态；页面切换不能重新生成不一致的数据。图表性能、最小高度和键盘操作都应以 1280x720 的原生 QML 截图验证。

### 11.6 Web 配置扩展

V2 的“指定业务”默认页面是包内外汇演示台，仍由 `web` 模块的本地 qrc 前缀允许；在线网页至少允许两个独立批准配置项（当前原型为百度和哔哩哔哩的展示入口）。为避免“一个模块只有一个 URL”与 V2 UI 矛盾，Manifest 扩展为：外部模块保留模块级隔离 Profile，并携带只读 `approvedPages[]` 子项，每项包含 `id`、`name`、`entryUrl`、导航/资源 Origin。QML 只选择 `id`，C++ 解析、校验与 URL 策略始终决定真正入口。

该字段升级需要同步更新 `ManifestService` 正反例测试和 `UrlPolicy`。未收到真实审批输入前，外网来源仅是演示清单，必须继续在 UI 和交付文档中声明不代表客户可访问来源。

### 11.8 已知门禁

- ARM64 的 Qt/QtWebEngine、构建通道和真机仍未关闭；V2 代码可先完成，但不能宣称 ARM64 已验证。
- 无受信任麒麟签名材料时，仅能交付和验证未签名基线包；目标机若强制包签名，须由客户/安全团队提供受控签名路径。
