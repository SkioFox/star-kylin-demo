# 行情终端参考分析与重构方向

> 阶段：UI 重构输入 ｜ 依据：`origin-ui-refer/` 中的自选、个股、行情、期货截图。
> 目标：吸收专业行情终端的任务组织方式，形成银行麒麟工作台的原创界面；不复制同花顺的品牌、图标、文案、视觉资产或具体布局比例。

## 1. 结论

此前原型把“高信息密度”主要做成了表格加一张 K 线，结果不同模块只是在复用相同结构，缺少行情终端应有的**标的上下文、数据联动和研究路径**。这不足以支撑“市场观察”作为工作模块。

参考界面值得吸收的是工作模型：

1. 当前标的是全页上下文，不是单独一张图。列表选中后，报价头、分时/K 线、盘口、新闻、资金、板块和关联信息都切换到同一标的。
2. 图表是分析画布，不是装饰。周期、指标、成交量、资金流、缩放和历史区间浏览都围绕同一个时间序列。
3. 页面按对象与场景分工。自选是扫描和发现；个股是单标的研究；行情是跨市场比较；期货是按交易所/品类监测，不应用同一数据表替代。
4. 信息密度依靠可对齐的数据格、固定报价区、底部行情带和稳定分栏，而不是层层卡片。

## 2. 参考功能模型

| 参考场景 | 核心任务 | 关键区域 | 对麒麟工作台的改造边界 |
|---|---|---|---|
| 自选 | 快速扫描、发现异动、切换研究对象 | 分组表、标的详情、分时/K 线、热点板块 | 保留自选与联动；不接入交易、荐股、社区或客户资产 |
| 个股 | 单标的研究与判断 | 自选列表、主图、盘口/资金、资讯、异动 | 保留研究链路；不做委托、买卖、账户或真实决策建议 |
| 行情 | 跨指数/板块/市场横向比较 | 分类页签、全量指标表、固定详情区、相关指数 | 保留国内/全球分组和比较；数据来源以后单独合规接入 |
| 期货 | 分交易所与品种监测 | 多交易所方格、选中合约图、期市要闻、关联标的 | 保留多窗格监测；不做期货交易或持仓功能 |

## 3. UI 模式拆解

### 3.1 稳定工作框架

```text
工作轨：身份 / 网络 / 服务 / 会话
├─ 模块导航：自选、个股、行情、全球、期货
└─ 任务上下文
   ├─ 标的或市场范围切换
   ├─ 主数据区：表格、研究图或多交易所看板
   ├─ 固定详情区：报价头、分时、K 线、热度/盘口
   └─ 辅助区：资讯、资金、关联板块、异动
```

右侧详情区必须有稳定宽度，避免用户在扫表时丢失“正在看谁”。主区承担当前页面的任务，不能每页只更换标题和相同表格。

### 3.2 标准图表画布

- **分时**：价格线、均价线、涨跌基准、量能和盘中时间；适用于交易时段的走势阅读。
- **K 线**：OHLC 蜡烛、至少两条 MA、成交量和 MACD；分时、日 K、周 K、月 K 应产生不同长度、波动和时间尺度的演示序列。
- **交互**：显式周期控件、放大、缩小、重置；滚轮缩放与拖拽查看历史区间。图表的可视数据窗口必须实际改变。
- **边界**：当前是本地演示序列与原型交互，不表示生产行情、实时刷新、交易建议或真实资金流。

### 3.3 数据表达

不同市场的样本应具备合理的量级和波动结构，而不是一组数字改标题：

| 场景 | 原型数据特点 |
|---|---|
| 银行指数 | 4,000 点级，低至中波动，受阶段性趋势和资金流解读影响 |
| 国内宽基 | 3,000 点级，日内波动收敛，适合自选/国内行情侧栏 |
| 全球指数 | 万点级，跨时区、较高波动幅度，适合全球市场页 |
| 商品期货 | 百点级，波动与量能脉冲更明显，适合期货合约详情 |
| 原生行情 | 宽基的高刷新视觉基线，与 Web 研究页有清晰实现边界 |

## 4. 重构目标

### M1 自选

- 左侧主体为可排序/可筛选的自选表，增加代码、现价、涨幅、涨跌、主力净流入、行业、换手等扫描字段。
- 右侧为选中标的的报价头、分时与 K 线双图、热点板块。点击表格行更新整个详情区。
- 分组、分时、日 K、周 K、月 K、缩放和平移真实生效。

### M2 个股研究

- 三栏研究台：左侧自选迷你列表，中间主图/指标/资讯/资金流，右侧报价与盘口、异动、关联板块。
- 研究信息围绕单一标的联动；K 线功能完整，不在页面上假装交易能力。
- **当前完成**：原型已实现五个研究对象切换；切换时工作区标题、报价头、开高低、K 线数据画像、五档价格和上下文内容共同更新。资金/资讯为当前演示对象的研究辅助信息，未接入真实行情或交易功能。

### M3 市场与全球

- “市场行情”按国内指数、A 股、板块热点、基金等分类；“全球市场”按美洲、欧洲、亚太及时区状态分类。
- 主表服务横向比较；详情侧栏显示选中指数的分时、K 线及相关指数，而不是复制自选模块数据。
- **当前完成**：国内市场按指数比较展示开高低和交易状态；全球市场按美洲、欧洲、亚太的会话状态展示，并默认联动标普 500 的走势、当日区间和相关指数。期货仍保持交易所矩阵，不与指数比较页复用结构。

### M4 期货

- 维持交易所/品类矩阵，但使用真实语义的合约名和针对期货的列：最新、涨幅、涨跌、日增仓/基差等。
- 下方为当前合约的分时/K 线与期市要闻，右侧补充关联品种；不同交易所面板不重复证券名称。
- **当前完成**：原型按上期所、郑商所、大商所、能源化工、金融期货、外盘期货展示真实语义的合约名称与“最新、涨幅、涨跌、日增仓”字段；点击合约会更新下方详情图和关联品种区。

### M5 黄金业务

- 不复用 ETF 或期货列表。主区以银行和产品为对象，比较买入价、卖出价、点差和更新时间；右侧以 `Au9999` 基准趋势和当前银行产品详情作为上下文。
- 当前原型通过本地数据验证“选中银行 - 报价详情 - 基准图”联动。真实数据必须先明确数据源授权、银行产品口径、延迟、交易时段和节假日规则。

## 5. 验收标准

- 每个市场模块有不同的信息结构、数据口径、图表数据和右侧详情，不以同一表格和同一曲线换标题。
- 图表周期切换后，数据根数、时间标签与波动结构变化；缩放/拖拽后可视窗口变化。
- 1366x768 下，主任务区、详情区和行情带仍可扫描，允许内容区滚动但不重叠。
- 所有行情、资讯与资金流仅为本地演示数据；不出现交易入口、客户数据、真实账户或生产能力暗示。

## 6. 实施顺序

1. 完成数据模型和交互图表基线，先消除所有曲线复用。
2. 用“自选 + 个股研究”建立标的上下文与联动结构。
3. 按国内/全球/期货的实际任务重写市场模块。
4. 截图复核后再冻结 UI，进入 Qt/QML 组件技术设计。
