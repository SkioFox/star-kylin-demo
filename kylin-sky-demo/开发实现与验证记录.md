### 下次验证命令

在已完成 T0A.3 的对应架构 Linux/麒麟构建机执行：

```bash
cmake -S kylin-sky-demo/app -B build/kylin-sky-demo -DCMAKE_BUILD_TYPE=Debug
cmake --build build/kylin-sky-demo --parallel
ctest --test-dir build/kylin-sky-demo --output-on-failure
cmake --install build/kylin-sky-demo --prefix stage/kylin-sky-demo
cpack --config build/kylin-sky-demo/CPackConfig.cmake -B dist
```

### DEB 安装签名门禁

- 2026-07-27 的修复包 `kylin-sky-demo_0.1.0-1_amd64.deb`（SHA-256：`5f9134c786605d07232e972db92b6e24b9af863e7fe5a831a735a17fd83af8f3`）经 `dpkg-deb --info/--contents` 检查，架构、动态依赖和文件清单正常。早期一次安装尝试曾报告“软件包验证失败，拒绝安装”，但 2026-07-29 复核 `/var/log/dpkg.log` 后确认同版本在 2026-07-27 已多次成功安装。因此该单次失败不能作为 VM 强制拒绝未签名包的结论。
- 根因已确认：该 VM 的 `dpkg` 启用 `verify-kylinsign`/`debsig-verify`，`kylinsigntool -v` 对当前 CPack 包返回“deb签名不存在”。VM 虽安装了 `kylinsigntool` 与 `kylinsigngetinfo`，但 `/etc/kylinsign/kylinsign.conf` 的 Root CA、开发 CA、私钥和用户证书均未配置。
- 处理边界：未签名基线包应先使用标准 `sudo dpkg -i` 在未强制签名的目标机验证；若客户目标明确拒绝，再从客户/安全团队获得受信任的麒麟签名证书、私钥或受控签名服务，生成签名变体并复验。任何情况下均不使用 `dpkg --no-debsig`、关闭 KySec 或修改目标机信任策略绕过。
- 额外环境风险：`kylin-verify` 在本次检查中提示服务周期将于 2026-07-29 到期；最终验收前应由环境管理员确认该 VM 的授权与安全基线仍有效。
