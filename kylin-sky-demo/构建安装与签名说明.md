# 麒麟工作台构建、签名与安装说明

> 适用范围：`kylin-sky-demo/app/` 的演示交付构件。
> 当前状态：amd64 麒麟 VM 已验证构建通道；ARM64 构建和两类真机验收未完成，不能据此宣称双架构可交付。

## 1. 构建前提

每个架构必须在同架构 Linux/银河麒麟构建通道执行。Intel Mac、Docker QEMU 或其他架构的结果不能代替对应麒麟真机结论。

需要的系统组件：CMake 3.16+、C++17 编译器、Qt 5.12+ 或 Qt 6（Core、Gui、Qml、Quick、QuickControls2、WebEngine、Test）、`dpkg-dev` 和 CPack DEB 支持。构建机需要拥有项目所依赖的 QtWebEngine 资源和许可证；交付包不包含 Node、CDN 或浏览器原型。

## 2. 架构构建

在项目根目录执行。`<release>` 必须随每个内容变更递增，避免同版本不同内容的安装包混淆。

```bash
cmake -S kylin-sky-demo/app -B build/kylin-sky-demo -DCMAKE_BUILD_TYPE=Release \
  -DKYLIN_SKY_PACKAGE_RELEASE=<release>
cmake --build build/kylin-sky-demo --parallel 2
ctest --test-dir build/kylin-sky-demo --output-on-failure
cd build/kylin-sky-demo
cpack -G DEB
```

构建产物名称由 CPack 按 CPU 自动标记，例如：

- `kylin-sky-demo_0.1.0-<release>_amd64.deb`
- `kylin-sky-demo_0.1.0-<release>_arm64.deb`

每次保存产物时记录：

```bash
dpkg-deb -f kylin-sky-demo_*.deb Package Version Architecture Depends
dpkg-deb -c kylin-sky-demo_*.deb
sha256sum kylin-sky-demo_*.deb
```

`Architecture` 必须和验收机的 `dpkg --print-architecture` 一致。

## 3. 自动化执行边界

构建、CTest、CPack、包字段/SHA-256 检查、标准 `dpkg -i` 安装尝试、已安装版本复核、命令行启动、开始菜单检查、卸载和日志/截图归档，均应由构建或验证自动化连续执行并留痕。不要把每一个常规步骤拆成手工确认。

以下动作必须停在受信任人员或受控服务处，不能用自动点击或策略降级代替：

- KySec 对内容变更后新 ELF 哈希弹出的本地执行授权；应只对明确的开发/验证路径作出人工选择，并在记录中说明结果。
- DEB 签名私钥、硬件令牌 PIN、证书口令和签名服务审批；它们不得传给自动化、写入仓库、Shell 历史或文档。
- 客户目标机的信任库、安全策略、全局 KySec 开关和 `dpkg` 验签策略；交付验证不得修改它们。

当上述门禁缺失时，自动化应继续完成安全的静态检查并明确报告“未安装/未执行”，而不是复用旧版本结果或试图绕过。

## 4. 未签名基线包与可选签名变体

每个架构首先交付 CPack 生成的未签名基线包。对未强制包签名的麒麟目标机，标准离线安装路径为：

```bash
sha256sum -c kylin-sky-demo_0.1.0-<release>_<arch>.deb.sha256
sudo dpkg -i kylin-sky-demo_0.1.0-<release>_<arch>.deb
```

客户已采集的 amd64 基线缺失 Qt WebEngine 库和 QML 模块时，必须使用 [客户离线安装包](./客户离线安装包/README.md) 的 `install.sh`，不得单独执行 `dpkg -i`。

不得因为存在签名能力而停止交付或测试基线包。签名是目标环境策略要求时的附加交付物，不改变应用功能、架构、依赖或安装路径。

部分银河麒麟环境的 `dpkg` 启用 `verify-kylinsign`/`debsig-verify`。CPack 只生成 DEB，不能生成受信任签名；是否强制拒绝未签名包必须以目标机实际安装结果为准。在此类强制环境中，未签名包会被拒绝安装。

受控签名构建机需要由安全团队配置受信任的麒麟签名私钥和证书，或提供等效签名服务。签名材料不得进入仓库、安装包、终端历史或演示脚本。

```bash
kylinsigntool -e kylin-sky-demo_0.1.0-<release>_<arch>.deb \
  -p <受控私钥路径> -c <受信任证书路径>
kylinsigntool -v kylin-sky-demo_0.1.0-<release>_<arch>.deb
kylinsigngetinfo -a -f kylin-sky-demo_0.1.0-<release>_<arch>.deb
```

若构建机已通过 `/etc/kylinsign/kylinsign.conf` 受控配置凭据，可在不暴露路径的前提下按安全团队流程运行相同签名命令。不得使用 `dpkg --no-debsig`、关闭 KySec、篡改目标机信任库或临时自签名绕过验收。

### 4.1 当前 amd64 VM 的签名事实

`star-kylin-amd64` 已安装 `kylin-signtool`、`certaide-kylin` 和 `kylinsigntool`，但 `/etc/kylinsign/kylinsign.conf` 只有示例注释，未配置 `RootCACert`、`DevCACert`、`PrivateKey` 或 `UserCert`，也未发现可用的项目签名证书/私钥。因此它只能验证“包未签名”，不能产生被该 VM 信任的签名包。

如果目标机拒绝未签名包，应从安全团队取得下列任一受控能力后再继续：受信任证书和对应私钥（通常由硬件令牌保护），或同架构受控签名服务。不要使用 `certaide-kylin` 随包的服务端示例密钥、APT 仓库公钥或临时自签名证书；这些都不构成客户/目标机认可的应用签名。

## 5. 离线安装与回归

将对应架构的离线包目录或压缩包、其 SHA-256、许可证清单、本说明和演示脚本经批准摆渡到目标机；若目标策略要求，再一并摆渡签名变体及签名验证结果。目标机无需访问互联网。

```bash
sha256sum -c kylin-sky-demo-offline-<arch>-<release>.tar.gz.sha256
tar -xzf kylin-sky-demo-offline-<arch>-<release>.tar.gz
cd kylin-sky-demo-offline-<arch>-<release>
sudo ./install.sh
dpkg-query -W -f='${Package} ${Version} ${Architecture}\n' kylin-sky-demo
/opt/kylin-sky-demo/bin/kylin-sky-demo
```

再从开始菜单打开“麒麟工作台”，并按《任务拆解》的 A01-A13、Web 边界、字体/DPI、输入法、20 次模块循环和卸载用例验收。卸载必须验证菜单入口、可执行文件和安装记录一并消失：

```bash
sudo dpkg -r kylin-sky-demo
```

## 6. 当前已知门禁

- amd64 本地 VM 的构建、CPack 和部分 GUI 冒烟已完成；`dpkg` 日志证明旧候选 `0.1.0-1` 曾可直接安装。后续候选包仍须在该 VM 与客户目标机分别执行实际安装检查，不能由 `kylinsigntool -v` 的“未签名”结果单独推导为必然拒绝。
- ARM64 需要原生 ARM64 Linux/麒麟构建与真机安装验收。
- QtWebEngine 的最终版本、系统 Qt/随包动态库策略、真实内网 Origin、本机应用路径和签名证书均应由对应环境基线与安全审批冻结。
