# 麒麟工作台需求分析与范围

> 版本：v0.3 ｜ 状态：UI 与技术方案已评审通过，实施任务拆解待评审
> 原始输入：[原始需求.md](./原始需求.md)；生产级安全边界仍以仓库根目录 `REQUIREMENTS.md` 及 `docs/design/` 为准。

## 1. 产品定义

**麒麟工作台**是运行在麒麟桌面的银行内部统一工作入口。它将身份、权限、受控 Web 系统、行情研究和本机工具组织在一个稳定的多任务外壳中，让柜面和运营人员在一个窗口内发现、打开、切换和恢复日常工作。

本轮定位为**完整交互的演示应用**：所有业务数据、登录结果、行情和网络响应都可为演示数据，但界面不得出现“Mock”字样、真实客户信息或真实凭据。它不能被描述为已经完成真实 CAS、权限中心、审计、国密或业务鉴权。

技术实现的组件边界、打包与双架构门禁见 [技术方案.md](./技术方案.md)。

## 2. 用户与核心任务

| 用户 | 典型任务 | 需要得到的结果 |
|---|---|---|
| 综合柜员 | 登录后查看自选、行情和指定业务系统 | 快速找到获授权模块，保持多个任务上下文 |
| 运营人员 | 查看市场概览、研究个股、打开运营 Web 系统 | 高密度阅读数据，在列表、图表、资讯间连续切换 |
| 平台演示人员 | 验证 Web 容器、网络能力、本机应用启动 | 清楚看到加载、限制、失败恢复和启动反馈 |

## 3. 目标与非目标

### 3.1 本轮目标

1. 提供用户名密码登录、登录中、失败和退出状态。
2. 依据演示角色呈现获授权模块，未授权模块不显示也不能被直接打开。
3. 提供统一工作台外壳：模块导航、可关闭工作标签、状态带、通知和会话信息。
4. 实现自选、个股、行情、全球、期货、黄金业务六个金融信息界面，数据为静态或本地生成数据。
5. 区分三类应用容器：指定内网 Web、受控外部 Web、Qt 原生高性能行情界面。
6. 提供 HTTP/HTTPS、SSE、WebSocket 请求状态验证与本机应用启动反馈。
7. 形成可在麒麟 x86_64 与 ARM64 后续落地的 UI 和交互基线。

### 3.2 明确不做

- 不接入真实登录账户、CAS、权限中心、客户、账户、交易或生产行情。
- 不执行交易、委托、资金操作，也不把行情页面包装为交易终端。
- 不允许用户在 Web 容器中任意输入网址，不下载文件、不绕过证书错误。
- 不把门户菜单隐藏视为业务操作权限；真实业务系统仍须由自身后端二次鉴权。
- 不把“在线网页”定义为面向客户交付的自由互联网浏览器。

## 4. 模块范围与容器策略

| 模块 | 主要价值 | 展示形态 | 本轮交互边界 |
|---|---|---|---|
| 工作台 | 任务入口与恢复 | 原生首页 | 显示收藏、最近打开、服务状态和授权模块 |
| 自选 | 关注标的快速扫描 | 原生表格 + 右侧详情 | 排序、筛选、选中一行更新详情；不保存真实偏好 |
| 个股 | 单标的研究 | 原生图表 + 指标 + 资讯 | 切换周期、指标、关联标的；不提供交易入口 |
| 行情 | 国内与全球指数概览 | 原生数据表格 | 分类切换、排序、详情联动 |
| 全球 | 主要市场跨时区概览 | 原生表格 + 时间状态 | 时区状态、指数分组、快速查看 |
| 期货 | 多市场品种概览 | 原生多窗格 | 分市场筛选、合约详情、行情状态 |
| 黄金业务 | 多银行贵金属报价查询与比较 | 原生表格 + 基准金价详情 | 显示产品、买入/卖出、点差、更新时间；不承诺真实报价、交易或申购 |
| 指定 Web 应用 | 行内 B/S 系统承接 | 受控 WebView | 仅清单入口、精确来源白名单、加载/拦截/错误恢复 |
| 在线网页 | 外部网页能力演示 | 独立受控 WebView | 仅批准的固定 HTTPS 示例来源；独立 Profile，不共享内部会话或 Bridge |
| 原生行情中心 | 高刷新图表展示 | Qt 原生页面 | 本地数据驱动，展示实时感图表和指标切换 |
| 网络验证 | 平台网络能力演示 | 原生诊断页 | 展示 HTTP、SSE、WebSocket 状态与错误恢复，不显示敏感请求内容 |
| 本机应用集成 | 与麒麟应用协作 | 原生启动反馈页 | 仅固定清单路径与参数；不经 Shell，不传递登录凭据 |

### 4.1 Web 应用配置模型

“指定业务”和“在线网页”都属于**由平台配置的内嵌应用**，不是让用户输入地址的浏览器。正式实现以签名 Manifest 为唯一配置来源；原型中展示的系统名、URL 和页面内容仅用于交互验证。

| 配置项 | 指定业务 | 在线网页 |
|---|---|---|
| `appId` | 固定的 `ops-workflow` | 由已批准清单选择，例如 `market-insights` |
| `name` / `entryUrl` | 固定的行内运营协同系统入口 | 每个批准外部页面各自配置入口 |
| 导航和资源来源 | 仅业务域及其审批的跳转/资源域 | 仅该外部应用获批的 HTTPS 域集合 |
| 会话与能力 | 按业务系统配置；业务系统仍二次鉴权 | 独立 Profile；默认无内部会话、JSBridge、下载和本机能力 |
| 用户可见操作 | 后退、前进、刷新 | 选择批准项、后退、前进、刷新 |

一个在线网页配置至少包含 `appId`、`name`、`entryUrl`、允许导航来源、允许资源来源、Profile 隔离策略和 Bridge 权限。配置变更必须走业务与安全审批，并重新签名；客户端不能通过 UI 添加或编辑 URL。

### 4.2 关键安全分层

指定 Web、在线网页和原生页面必须在 UI 上可识别，但不能伪造“已安全认证”之类结论。

- **指定 Web**：来源、导航、资源、下载、弹窗和原生能力按签名清单控制。
- **在线网页**：外部域名使用独立 Profile，默认不授予 JSBridge、本机会话或下载权限；用户只能从已经审批、签名的配置清单切换页面，最终允许来源由业务和安全审批。
- **原生模块**：高刷新数据不经过 WebView；拉起外部应用只允许固定绝对路径和受限参数。

## 5. 信息架构

```text
登录
  └─ 工作台
      ├─ 我的工作：收藏 / 最近打开 / 待处理状态
      ├─ 市场观察：自选 / 个股 / 行情 / 全球 / 期货 / 黄金业务
      ├─ 应用服务：指定 Web / 在线网页 / 网络验证
      ├─ 原生能力：原生行情中心 / 本机应用集成
      └─ 已打开标签：每个模块单实例，可关闭并回到工作台
```

左侧导航负责“发现与进入”，顶部标签负责“已打开任务切换”，两者不混用。工作台标签固定存在；同一模块重复打开时只激活既有标签。

## 6. 状态与验收重点

| 场景 | 必须可见的状态 | 可执行动作 |
|---|---|---|
| 登录 | 默认、校验失败、提交中、登录成功 | 提交、修正输入、退出 |
| 模块访问 | 有权限、无权限、首次加载、已打开 | 打开、激活既有标签 |
| Web | 加载、成功、来源被阻止、网络失败、证书失败 | 后退、前进、刷新、查看阻断原因 |
| 行情 | 正常、刷新中、无数据、刷新失败 | 切换周期/指标、重试、重置视图 |
| 黄金业务 | 报价覆盖正常、单银行报价过期、基准数据不可用 | 选择银行、刷新报价、切换基准金价周期、重置视图 |
| 网络验证 | HTTP/SSE/WS 连接中、已连接、重连、失败 | 发起、断开、重试 |
| 本机应用 | 可启动、启动中、未安装、被策略拒绝、启动失败 | 启动、重新检测 |

## 7. 需求拆分与实施状态

正式任务拆解见 [任务拆解.md](./任务拆解.md)。实施按以下顺序组织，而不是同时实现所有模块：

1. 外壳、登录、权限过滤、工作台和标签体系。
2. 设计系统、表格/图表/状态组件与键盘焦点。
3. 市场观察模块：先自选、行情、个股，再扩展全球与期货。
4. 指定 Web、在线网页、网络验证和本机应用集成的安全交互。
5. 原生行情中心、高刷新图表、安装包、双架构与麒麟真机验证。

## 8. 设计确认项

以下信息缺失时，不应在技术方案中假定已经解决：

1. 最终首批行内 Web 系统、入口域名、重定向域名、资源域名和是否允许下载。
2. 企业认证与门户身份闭环方式，及权限中心实际模型。
3. 哪些角色可使用外部网页与本机应用启动能力。
4. 客户麒麟版本、Qt/QtWebEngine 基线、x86_64 与 ARM64 验收机。
5. 真实市场数据来源、授权、刷新频率和红涨绿跌本地化约定。
6. 黄金业务的首批银行、产品分类（积存金/实物金）、数据源授权、报价口径、更新时间和节假日规则。

## 9. 本轮 UI 验收门槛

- 首屏是可直接工作的登录或工作台，不做营销落地页。
- 1366x768、1440x900 和 150% 缩放下，导航、图表、表格与状态带不重叠、不截断。
- 所有按钮具备默认、悬停、按下、禁用和键盘焦点状态；颜色不是唯一状态信息。
- 表格数字等宽对齐，涨跌同时以符号、文本和颜色表达。
- 加载与错误不改变容器尺寸；用户可明确知道下一步可做什么。
- 指定 Web 与在线网页的来源、联网和受限状态表达准确，不给用户制造“任意网页均可访问”的预期。
